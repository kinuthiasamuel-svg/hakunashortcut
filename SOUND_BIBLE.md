## PART 02 — THE THREE-LAYER ARCHITECTURE

```
LAYER 01 — ELECTRICAL HUM      Constant. The foundation.
LAYER 02 — TRANSMISSION STATIC  Periodic. The interference.
LAYER 03 — NODE LOCATED         Random. The discovery.
```

These three layers are never all equal in volume.
They have a hierarchy. The mix is intentional.

---

### LAYER 01 — ELECTRICAL HUM

**Role:** Foundation. Constant field presence.
**Character:** Deep, industrial, alive.

**Technical specification:**
- Primary oscillator: Sawtooth wave at 52Hz
- Sub layer: Sine wave at 26Hz (one octave below)
- Filter: Low-pass at 180Hz, -24dB rolloff
- Movement: Slow tremolo at 0.08Hz, 15% depth
- Default volume: `-18dB`
- Sub layer volume: `-24dB`

**Why sawtooth:** Sawtooth waves contain all harmonics —
they sound electrical, mechanical, inhabited.
A sine wave would be too clean. Too empty.
A sawtooth sounds like something is running.

**Mixing rule:** The hum should be felt more than heard.
If the listener is consciously noticing the hum — it is too loud.
It should register as environment, not sound.

---

### LAYER 02 — TRANSMISSION STATIC

**Role:** Periodic interference. Proof of signal.
**Character:** Unpredictable, brief, authentic.

**Technical specification:**
- Source: Brown noise (warmer than white, heavier than pink)
- Filter: Bandpass at 2200Hz, Q: 0.4
- Burst duration: 80–260ms (randomized)
- Burst interval: 3–12 seconds (randomized)
- Attack: 20ms (fast but not instant)
- Release: Tail to zero
- Default volume: `-28dB`

**Why brown noise:** Brown noise has more energy in the low-mid
frequencies — it sounds like radio interference, distant transmission,
corrupted signal. White noise would feel digital and clean.
Brown noise feels analogue and aged.

**Mixing rule:** Static should surprise without startling.
The burst should register as signal decay — a reminder that
the connection is maintained through imperfect infrastructure.
If the listener flinches — it is too loud.

**Visual indicator:** Static flash in the UI —
a brief flicker on the TRANSMISSION STATIC layer label.

---

### LAYER 03 — NODE LOCATED

**Role:** Random discovery. The transmission event.
**Character:** Sharp, precise, significant.

**Technical specification:**
- Oscillator: Sine wave (pure, high-frequency)
- Frequency range: 880Hz–1320Hz (randomized per ping)
- Envelope: Attack 5ms / Decay 800ms / Sustain 0 / Release 1.2s
- Interval: 8–30 seconds (randomized — never predictable)
- Default volume: `-22dB`
- Each ping: New synth instance, disposed after 3 seconds

**Why randomized frequency:** A fixed ping becomes a metronome —
the ear adapts and ignores it.
A randomized frequency keeps the listener alert.
Each ping feels like new information.

**Why never predictable:** Predictable = ignored.
Random = meaningful.
The ear assigns significance to events it cannot anticipate.

**The transmission protocol:**
When a ping fires, the status display switches from:
`AMBIENT: ACTIVE` → `▶ INCOMING TRANSMISSION`

This state holds for 2 seconds then returns to ambient.
This is the moment sound alone communicates:
*something has been found.*

**Mixing rule:** The ping should cut through the hum and static
cleanly. It is the only layer designed to be consciously noticed.
It should feel like information arriving — not an alert, not an alarm.
A quiet confirmation that the system is working.

## PART 03 — THE MIX

### The Hierarchy

```
LOUDEST   →   NODE LOCATED ping    (-22dB)
MIDDLE    →   ELECTRICAL HUM       (-18dB)
QUIETEST  →   TRANSMISSION STATIC  (-28dB)
```

Note: The hum sits above the static by design.
The foundation is louder than the interference.
The infrastructure is more present than the noise within it.

### The Volume Law

**Law 01:** No single layer should dominate the mix.
The three layers exist in relationship, not competition.

**Law 02:** The mix should feel like a room, not a track.
The listener should be able to stop noticing it —
and then suddenly notice it again when a ping fires.

**Law 03:** Mobile listening context.
The primary listening environment is a phone speaker
or earbuds while reading on mobile.
Mix decisions reflect this — no sub-bass reliance,
midrange presence maintained.

## PART 04 — THE INCOMING TRANSMISSION PROTOCOL

This is the most important sonic rule in the document.

> **Sound alone = incoming transmission.**

The moment the ambient is activated — before any visual,
before any text, before any image — the reader is receiving.

This protocol governs how that moment is designed:

**Step 01 — Activation**
The reader presses `ACTIVATE SIGNAL`.
The hum begins. The field is live.

**Step 02 — Settling**
Static bursts begin within 2–4 seconds.
The environment establishes itself.

**Step 03 — First Ping**
The first NODE LOCATED ping fires between 4–12 seconds.
The status switches to `▶ INCOMING TRANSMISSION`.
The reader knows: *something is here.*

**Step 04 — Ongoing Field**
The ambient continues indefinitely.
Pings fire at random. Static interrupts at random.
The hum never stops.

**Step 05 — Termination**
`TERMINATE SIGNAL` — all layers stop.
Silence is the cut to black.
The transmission is complete.

## PART 07 — TECHNICAL NOTES

### No Audio Files Required

The Sound Module generates all audio procedurally using Tone.js.
This means:

- Zero file hosting costs
- Instant load — no buffering
- Infinite variation — never exactly repeats
- Full control over every parameter

### Browser Requirement

All modern browsers support the Web Audio API.
The module requires a user interaction (button press)
before audio can start — this is a browser security requirement,
not a design choice.

### Mobile Compatibility

The Sound Module is optimized for mobile-first listening.
Tone.js handles AudioContext management across iOS and Android.
